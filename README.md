# Luckgram Desktop

Luckgram for Windows (and, from M1, macOS), built on
[Telegram Desktop](https://github.com/telegramdesktop/tdesktop).

- **Upstream version:** Telegram Desktop **v7.4.2** (tag `v7.4.2`, stable).
  The full upstream history and submodules are kept in this repository.

- Upstream's original README: [README.upstream.md](README.upstream.md).
- Plan and specs: `limeng9088/luckgram-specs`, `docs/desktop.md` and
  `specs/desktop/` (D1–D4, M1, M2).

## What Luckgram changes (D1)

| Area | Change |
|---|---|
| Brand | Name "Luckgram", Luckgram icon (`luckgram/branding/icon-1024.png`, generated by `luckgram/tools/make_icons.py`), window title, tray, about page. "Telegram Desktop" in language packs is shown as "Luckgram". |
| Side by side with Telegram Desktop | Own AppId (installer / uninstall key), AppUserModelID `Luckgram.LuckgramDesktop`, toast activator CLSID, Start menu shortcut, data folder `%APPDATA%\Luckgram`, single-instance lock (by exe path). |
| `tg://` links | Not registered on first launch. Settings → Advanced → "Open tg:// links with Luckgram" (off by default) registers / removes it, under Luckgram's own registry names. |
| Updates, crash reports | Upstream updater and crash report upload are compiled out (`DESKTOP_APP_DISABLE_AUTOUPDATE`, `DESKTOP_APP_DISABLE_CRASH_REPORTS`). In-app update comes with D4. |
| Language | Chinese system → Telegram's Simplified Chinese language pack (`zh-hans-beta`) on first launch; other systems → English. |
| API credentials | `api_id` / `api_hash` come only from the Actions secrets `TG_API_ID` / `TG_API_HASH`; CI fails without them. |
| Build info | About page shows version, build number (CI `run_number`) and commit. |

Luckgram code lives in `Telegram/SourceFiles/luckgram/`,
`Telegram/cmake/luckgram.cmake` and `luckgram/`. Changes to upstream files are
one-line hooks marked with a `Luckgram` comment, so upstream merges stay small.

## Builds

`.github/workflows/build.yml` runs on pushes to `master`, pull requests and
manual dispatch, on GitHub-hosted Windows runners:

1. **Libraries** builds Qt and the other dependencies with
   `Telegram/build/prepare/prepare.py` and caches them. Later runs skip this
   job. If a first run hits the time limit, the next run continues from the
   saved progress.
2. **Luckgram x64** builds Release and uploads two artifacts:
   - `Luckgram-Setup-<version>-<build>-x64.exe`: Inno Setup, per user, no
     admin rights, installs to `%LOCALAPPDATA%\Programs\Luckgram`, Start menu
     plus optional desktop shortcut. The uninstaller removes the program
     folder and asks whether to delete chat data (default: keep).
   - `Luckgram-<version>-<build>-x64-portable.zip`: unzip and run. The
     `luckgram-portable` file next to `Luckgram.exe` keeps data in that folder.

Version = upstream version (`AppVersionStr`), build = `github.run_number`.
Builds are **unsigned** for now ("未签名" in the log). Signing turns on when
the secrets `WINDOWS_SIGN_PFX_BASE64` and `WINDOWS_SIGN_PFX_PASSWORD` exist.

Don't build the whole app on a small machine; use CI. For a local build,
follow [docs/building-win-x64.md](docs/building-win-x64.md) and add
`-D TDESKTOP_API_ID=... -D TDESKTOP_API_HASH=...` with your own credentials.

## Syncing upstream

Merge new upstream **stable** tags (not betas). Don't rebase and don't rewrite
history:

```sh
git remote add upstream https://github.com/telegramdesktop/tdesktop.git  # once
git fetch upstream --tags
git checkout -b chore/upstream-vX.Y.Z master
git merge vX.Y.Z           # resolve conflicts in the Luckgram hooks
git submodule update --init --recursive
```

Then open a PR and let CI build it. Check that a tag is stable with
`git show vX.Y.Z:Telegram/SourceFiles/core/version.h | grep AppBetaVersion`;
it must be `false`.
